# llmff v1.1.0

`llmff` v1.1.0 adds bounded loop and map execution primitives plus typed JSON
stages for inspectable refinement, tool-loop, selection, and batch-item
workflows.

## Added

- `op: loop` with required `max_iterations`, explicit `break_on`, and embedded
  body stages.
- `op: map` with required `max_items`, default sequential execution, and
  opt-in bounded parallel execution via `parallel: true` plus
  `max_concurrency`.
- JSON body helpers: `extract`, `predicate`, `accumulate`, `score`, and
  `select`.
- Loop iteration retention for downstream selection patterns.
- Loop output metadata with `iterations_run`, `stop_reason`, and `final_stage`.
- Trace and event loop context fields: `loop_id`, `loop_iteration`, and
  `loop_stage_id`.
- Trace and event map context fields: `map_id`, `map_index`, and
  `map_stage_id`.
- `inspect --format json` loop metadata showing body size and maximum expanded
  stage count.
- Offline v1.1 loop examples for self-refine, ReAct-style tool use, best-of-N
  selection, iterative fact checking, and bounded map.
- Compatibility with the existing Python subprocess supervisor, batch supervisor,
  Node.js streaming supervisor, agent runner adoption guide, OpenTelemetry bridge,
  and ecosystem readiness gates.

## Boundary

Loops and maps are bounded execution stages. They are not a scheduler, memory
system, policy engine, or autonomous planner.
