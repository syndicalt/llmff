# llmff v1.0.0

This file is the guarded release-note draft for the final v1.0 release. Do not
publish `v1.0.0` until the compatibility review in `docs/release-readiness.md`
and `docs/v1-contract.md` is complete.

## Supported Install

```bash
cargo install --git https://github.com/syndicalt/llmff --tag v1.0.0 llmff
```

## Release Bar

`v1.0.0` may ship only after:

- required local and CI gates pass;
- every stable CLI, manifest, plugin, trace, event, result, and library surface
  is covered by docs, tests, schemas, or fixtures;
- package artifacts build and smoke-test on their target platforms;
- dependency and security review is complete;
- `docs/migration/pre-1.0-to-1.0.md` is complete;
- no release note, package metadata, or launch material claims sandboxing,
  signing, provider certification, package-manager publication, or live-smoke
  verification without matching evidence.

## Included Since v0.8.0

- The stable contract in `docs/v1-contract.md` is reviewed and promoted for
  v1.0.
- The v0.8.0 release candidate verified install, release assets, docs, examples,
  plugin template adoption, and supervisor integration assumptions.
- The Python subprocess supervisor, batch supervisor, Node.js streaming supervisor,
  agent runner adoption guide, OpenTelemetry bridge, ecosystem readiness checks,
  and release preflight are part of the production release gate. Release preflight
  remains the local release metadata gate.
- Dependency and security review evidence is recorded in
  `docs/release-evidence/v1.0.0-security.md`.
- Failure diagnostics, run-directory artifacts, JSON schemas, discovery
  fixtures, plugin protocol v1 behavior, provider support tiers, and
  reproducibility guidance have stable evidence-backed documentation.

## Known Limitations

- `llmff` remains a bounded pipeline runner, not an agent framework, memory
  system, scheduler, model server, native inference kernel, or multimodal
  engine.
- Windows and macOS native artifacts are unsigned in this release.
- Package-manager distribution through Homebrew, winget, Scoop, apt
  repositories, or an official AUR package remains parked until maintainers
  decide those channels are support-ready.
- Live provider smoke jobs remain opt-in and require maintainers to configure
  credentials explicitly.
